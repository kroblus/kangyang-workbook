# 数据、附件与完整备份

## 持久模型

Room schema 1 保存 `entries`、`drafts`、`attachments`、`sealed_drafts`、`restore_rollback`。Entry 的 Kind 明确区分单位、客户、联系人、服务对象、沟通、活动、待办、本人资料。`parentId` 和 `sourceId` 是稳定标识引用，不用姓名作关系键；多名联系人和服务对象是独立行。字段 Map 是各业务实体的可扩展属性，关系、实体类型、发生/创建/修改时间、归档状态为独立列。

所有 Repository 写操作通过 Mutex 串行化，相关行在 Room 事务中落盘。没有 destructive migration；本轮为新库 schema 1，没有实际升级迁移可宣称已测。Room 导出 schema 保存在 app/schemas。

正式沟通和跟进使用稳定 ID：一条沟通默认只关联一个 `followup-<记录ID>` 待办。编辑正文不会重置已独立改期的待办；只有下一步相关字段确实改变才更新对应待办，完成状态保留。重新关联临时速记时同步关联待办的对象。单位/客户归档保留历史和待办。有依赖关系时拒绝物理删除并提示归档。活动取消与选择取消的未完成筹备事项在同一事务更新。

草稿独立持久保存并比较 revision。提交和丢弃将草稿 ID 持久封存；迟到回调不能重新写入。同版本相同内容重复写是幂等成功，旧版本拒绝。附件 ownerId 指向草稿内部的 Entry ID，转正式不改变归属。

## 附件

系统选择结果以 ContentResolver 读取，复制到 APP 私有 `files/workbook/attachments/<SHA-256>.bin`。每个附件最多 20 MB，支持 JPEG、PNG、WebP、GIF、PDF、文本、CSV、常见 Office 与 ODT；部分格式额外核验文件头。实际字节流同样受限，不信任文件提供方报告的大小。空文件、超限、不支持格式、读取失败、内容不匹配、空间不足都会抛出可显示错误；已存在草稿不被删除。

先写临时文件并 fsync，再重命名为内容寻址的不可变文件，最后落元数据。元数据成功前不会报导入成功。预览/分享校验大小与 SHA-256。取消/移除仅移除已确认的引用；物理文件保留给最近恢复的回滚快照。因此长期反复添加/删除附件会多占空间，首版没有自动垃圾回收或清理个人数据的按钮。

## 业务导出

CSV 与文本摘要不是备份。CSV 使用 UTF-8 BOM、CRLF、RFC 风格双引号转义。以 `= + - @` 开始（包括前导空白/控制字符）的文本加单引号，阻止电子表格公式执行；不会生成伪装文本的公式。CSV 本身没有列类型，电话号码等需要在表格软件导入时选“文本”列，避免前导零丢失。不会声称 CSV 是 XLSX。

默认导出只含名称、对象、时间、方式、确认程度等结构字段。正文、结论、下一步、活动方案等自由文本需主动打开 `includeBody`；自由文本可能含个人信息，导出前必须查看预览。结构化电话、微信和照护信息由独立 `includeSensitive` 选项控制，默认关闭。界面负责提供当前筛选/全部范围、系统文件保存和系统分享面板，应用不选择接收人、不自动发送。

## 口令备份与恢复

`.kywb` 是版本化、可移机解密的备份。加密为标准 AES-256-GCM（128-bit tag、随机 96-bit nonce），口令派生为 PBKDF2-HMAC-SHA256（600,000 次、随机 128-bit salt）。头部被 GCM AAD 认证。口令至少 8 字符、不存入备份、不依赖手机 Keystore、无法找回。导出期间持有数据/附件写锁，由 Room 事务读一致逻辑快照，不直接复制可能遗漏 WAL 的数据库文件。

包内含数据版本、应用版本、备份时间、全部实体/稳定关系、草稿、已提交草稿封存历史、本人资料、附件元数据和原始字节。提醒调度本身不备份，恢复后按有效业务状态重建。只供界面表现的 DataStore 偏好不属于业务资料；业务时区固定 Asia/Shanghai、标签和本人配置包含在 Profile。

读取包时限制口令长度/KDF 参数、密文总量（80 MB）、解压总量（64 MB）、清单大小（16 MB）、单附件（20 MB）、文件数量和业务条数。拒绝路径穿越、未知/重复 ZIP 项、未来数据版本、缺失或多余附件、重复标识、悬空/类型不匹配关系、校验不符、已提交草稿复活。先完成口令、全部关系和每个附件校验，再提供恢复范围预览；此时没有修改当前资料。

确认后：不可变新附件先落盘并 fsync；全部准备好后以一个 Room/SQLite 事务保存当前完整逻辑回滚快照并替换业务表。事务前进程中断只留下无引用新文件，旧数据库完整；事务提交后新库和所需附件完整。旧文件保留，所以最近恢复支持回滚。数据库崩溃恢复由 SQLite 事务/WAL 保证，不依赖恢复期间主进程保持运行。

`BackupManager.restore` 的 checkpoint 参数只供测试控制：`validated`、`files_staged`、`committed`。它没有生产界面入口，测试使用独立 .qa 包和 UUID 命名的独立数据库/存储目录。

## 可运行验证

- `BackupAndExportTest`：口令/密文篡改/KDF 参数；未来版本、异常路径、缺失/损坏附件；CSV 中文/逗号/引号/换行/公式防护、默认敏感字段排除；悬空关系/角色；严格时间与草稿。
- `RepositorySafetyTest`：真实 Room 重复提交、迟到草稿、独立改期、主联系人唯一、归档依赖；包含所有实体/草稿/附件的加密备份在独立空空间恢复、校验/回滚；事务前故障注入；活动取消和独立日期保留。
- `RestoreProcessRecoveryTest`：由主机显式运行 `prepareInterruption`，读到 `files/restore-interruption-ready.txt` 后强制停止仅 .qa；重新启动 instrumentation 的 `verifyAfterInterruption` 验证旧库完整。需参数 `-e interruptRestore true`，普通全套运行会跳过这两项，不能把跳过写为通过。

以上是已实现测试，执行结果由主代理运行后写入 docs/ACCEPTANCE.md；本文不预先宣称通过。
