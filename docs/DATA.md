# V1.1 数据、附件与完整备份

## 数据库升级

V1.1 保留 Entry、Attachment、草稿、封存历史和回滚快照。Room schema 从1升至2，增加 `note_sessions` 表以及 drafts 的 `isNoteBuffer`、`baseUpdatedAt`、`recoveryReason` 列。迁移仅新增结构，不删除旧业务行、不改包名、不使用破坏性迁移。schema 文件位于 `app/schemas`。

Entry 的 kind、parentId、sourceId、发生/创建/更新时间和归档状态仍是独立列。字段 Map 保存各业务字段；关系用稳定标识，通过保存事务和全量备份校验核对。

## 保存与旧内容处理

正文连续保存独立于一次性表单提交。每个记录只允许当前持久 note session 写入；revision 不能倒退，同 revision 不允许不同内容。一次事务同时写编辑缓冲和正式沟通记录。无效的新空白会话不会发布；非空正文或归属正确的成功附件可发布；已有记录清空后仍保留同 ID。

编辑层在350ms停止输入后请求写入，持续输入时也以1500ms最长调度间隔请求最新内容。落盘仍受实际 I/O 影响。“已保存”只对应最新内容版本的成功提交；附件导入状态单独显示，不代替正文状态。返回与完成等待最后一次提交，失败仍留在编辑页并提供重试。强制结束发生在提交前时，尚未落盘的输入不能保证保留。

旧沟通草稿在启动时兼容转换，新建草稿保持原 Entry ID、附件归属、标题、关联、发生时间和更多字段。有效草稿进入新的记录查找路径；非法时间或关系保留为待整理内容；普通客户、单位等草稿不自动提交。已有正式记录更新晚于旧编辑基线时，保留正式内容及冲突草稿供明确选择。迁移消费的草稿 ID 封存，重复启动不重复发布，不自动创建跟进。

V1 正式沟通的 occurredAt 一直是时间线和导出的事实来源。对旧 UI 留下的不一致日期字符串，V1.1 保留该字符串供追溯，并从原 occurredAt 对齐显示字段，不擅自把历史谈话移动到另一时间。非法旧草稿不静默纠正为成功。

TASK 独立维护标题、日期、时刻、提醒、优先级、状态与完成备注。正文保存不写这些字段；标题修改使用 patch，独立改期不会被来源记录的 next* 旧值覆盖。状态切换未传备注时保留原备注。重新关联沟通只同步 TASK 的归属，不改任务其他事实。

## 附件

系统选择结果通过 ContentResolver 读取，复制到私有 `files/workbook/attachments/<SHA-256>.bin`。导入前先持久建立内部 owner；每个文件最多20 MB，支持 JPEG、PNG、WebP、GIF、PDF、文本、CSV、常见 Office 与 ODT。实际读取字节同样受限，部分格式核对文件头，不信任提供方报告大小。

先写临时文件并 fsync，原子重命名到内容寻址文件，最后提交附件元数据及归属。取消/导入失败不留下可见空沟通；正文或有效附件已存在时不损坏原内容。正文与附件状态分别按实际结果显示。进程恰在附件元数据成功后、首次正文发布前结束时，启动转换会把合法附件缓冲找回为附件记录。

预览/分享再次核对大小和 SHA-256。缺失、损坏、不支持、超限或空间不足均反馈失败。移除只去掉选中的引用，旧物理文件为最近恢复的回滚保留；本轮没有自动垃圾回收或清理资料按钮。附件名可搜索，不提供 OCR 或 PDF 内文搜索。

## 导出

业务导出不是完整备份。CSV 使用 UTF-8 BOM、CRLF 和双引号转义；包括前导空白/控制字符的公式前缀用单引号中和，不伪造公式。CSV 没有列类型，电话列导入表格软件时需选择文本。

默认仅导出基本结构字段和附件名称。详细正文、结论和下一步需主动选择；结构化电话和照护信息有独立开关。下一步来自当前 TASK，旧 nextStep 仅在没有对应任务时注明为旧建议。纯附件/清空记录和待定活动使用当前语义的可读摘要。

UI 预览是普通记录内容，不直接显示 CSV 转义语法。预览时固定范围、快照、字段开关和导出字节，避免预览与保存使用不同数据。保存经系统文件选择器；分享仅打开系统选择面板，不自动选择接收方或发送。

## 备份版本与完整性

`.kywb` 新导出数据语义版本为2，加密封装仍是 framing 1。V1.1 支持合法 V1 数据语义版本1；V1 无须、也不承诺能读取 V1.1 新形态。读取旧包按源版本先验证，再转换旧草稿并按当前契约验证；不能用转换掩盖非法来源关系、缺失附件或损坏数据。

加密仍为 AES-256-GCM，随机96-bit nonce、128-bit tag、随机128-bit salt。口令通过 PBKDF2-HMAC-SHA256（600,000次）派生密钥，头部纳入 GCM AAD 认证。新备份口令至少8字符，不存入口令文件、不依赖原手机 Keystore，无法找回。

导出持有数据/附件写锁并读取 Room 一致事务快照，不直接复制可能遗漏 WAL 的数据库文件。包内包含全部实体、稳定关系、草稿、封存历史、本人业务配置及附件字节。当前编辑会话表和系统闹钟不迁移；业务资料恢复后重新建立会话与有效提醒。

限制保持为：密文包80 MB、解压后总量64 MB（含清单）、清单16 MB、单附件20 MB，同时限制KDF参数、条目数量与路径。拒绝异常或重复 ZIP 项、未来语义版本、缺失/多余附件、悬空/类型不匹配关系、校验错误及已封存草稿复活。

## 恢复、回滚与数据会话

设置将“备份资料”和“从备份恢复”分开。恢复先读包并校验完整内容，再显示时间与各类数量，确认完整替换范围；确认前不修改资料。

生产 UI 只能通过 ViewModel `restoreData` 进入恢复/回滚。该入口取消并等待在途正文、附件和保存任务，失效页面会话，清空旧 editor/导航/导出状态。底层恢复和回滚在等待 mutationMutex 前推进 generation，事务提交前再次检查代次；旧会话的 onStop、迟到保存或附件回调不能进入恢复后的库。跨进程不存在旧进程回调，持续编辑的身份由 Room 会话和封存历史保证。

所有新附件先校验、暂存、fsync、原子重命名，再用一个 Room 事务保存旧完整回滚快照并替换业务表。事务前中断仅留下未引用文件，旧库完整；提交后新库及所需附件完整。旧文件保留，支持一次恢复前快照回滚；回滚也经过同样的会话隔离。

`beforeNoteCommit`、`beforeAttachmentCommit` 与 restore checkpoint 是受控测试接口，没有生产 UI 入口。实际进程中断、旧备份兼容及失败重试的本轮执行结果只见 [ACCEPTANCE](ACCEPTANCE.md)，不把测试存在等同于测试已通过。
